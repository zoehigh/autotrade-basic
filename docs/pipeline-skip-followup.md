| 브로커 | ~10-30 (서머타임) | 11-02 (동절기 첫날) | 11-03 이후 (동절기) |

- 외부 스케줄러 설정은 저장소에 없어 **ET 시간대 설정인지, 전환 때 사람이 옮긴 것인지 미확인**입니다.
  수동 이동이라면 2027-03-15 에 되돌리지 않으면 20:15Z/20:20Z 가 마감 후가 되어 SKIP 됩니다.
  KIS 의 현재 항목이 "19:10 UTC" 인지 "14:10 ET" 인지도 동절기 이력만으로는 구분되지 않습니다.
- KIS 11-02 실패 원인: `모의투자: 예약주문 가능시간이 아닙니다` (KST 05:10).
  `src/broker/kis/market_hours.py` 의 서머타임 분기가 **반대**입니다. 미국 정규장은 서머타임에 KST
  22:30~05:00, 동절기에 23:30~06:00 인데 코드는 뒤집혀 있습니다. KIS **모의** 주문 경로에서 쓰이며,
  동절기 KST 05:00~06:00(ET 15:00~16:00) 주문이 거부됩니다. **별도 수정 과제** (이 PR 범위 밖).

  마감 주문 접수 마감의 영향을 받지 않습니다. 대신 **실행 시각의 시세**에서 지정가가 체결될 수 있어, 시각을
  바꾸면 체결 결과가 달라질 수 있습니다. Kiwoom 은 정규장 밖 주문이 거부됩니다(어댑터 주석, RC4058).
  NHPlug 의 장외 접수 여부는 미확인입니다.
- **거래소 마감 주문(실전 참고)**: Nasdaq MOC 15:55 / LOC 15:58 ET, NYSE Arca 는 마감 1분 전부터
  imbalance freeze(반대편 주문만 접수). 웹 검색 결과이며 규정 원문 확인이 필요합니다. 조기폐장일 마감 규칙,
  KIS·Kiwoom·NH 의 해외 LOC/MOC 자체 접수 마감은 **미확인**.
- **Actions 지연 여유**: 최근 dispatch 의 시작 지연은 중앙값 1분 미만, 성공 실행 전체 중앙값 1.4~3.5분
  (최대 6.5분, #26 이전 실행 위주). **LIFECYCLE 체인의 성공 실행 시간은 아직 표본이 없습니다.** 마감 40분 전
  시작은 이 범위에서 여유가 있습니다. 마감 후에 시작하면 실패가 아니라 SKIP 이 됩니다.
- **판단**: 현행 시각은 pipeline 의 거래일 판정과 충돌하지 않으므로 **바꿔야 할 이유가 없습니다.** 후보도
  판정상 안전하고 DST 작업이 없어지지만, 동절기 Kiwoom·NHPlug 실행이 1시간 빨라집니다. 바꾼다면 거래가 없는
  시간에 바꿔 **같은 날 두 번 dispatch 되지 않게** 해야 합니다.

## 2. `us_order_window()` 와 `broker.is_trading_day()` 불일치

재현(실제 XNYS 캘린더, Mock 브로커): 대상 세션은 열려 있지만 ET 달력 날짜가 휴장인 시각의 EXECUTE.

| 시각 | `RUN_PHASE=EXECUTE` 디스패처 | AUTO_EXECUTE 경로 |
|---|---|---|
| KST 월요일 10:15 (ET 일요일 저녁) | **실패, 주문 0건** | 대기 후 실행 |
| KST 휴장 다음 날 10:15 (ET 휴장일 저녁) | **실패, 주문 0건** | 대기 후 실행 |
| KST 화요일 10:15, 월요일 14:00·18:30 | 실행 | 실행 |

- **정상적인 다음 세션 실행을 막습니다.** main 도 같은 검사(`is_trading_day`)를 하며, 정상 SKIP 이 아니라
  실패로 드러납니다.
- 영향: self-hosted(Kiwoom·Toss real) 의 아침 LIFECYCLE/EXECUTE. hosted 기본 설정에서는 같은 시각의 대기가
  4시간을 넘어 게이트에서 먼저 실패합니다. 로컬 cron 의 18:30 EXECUTE 는 영향이 없습니다.
- **이 PR 에는 수정을 포함하지 않습니다** (후속 과제).

## 3. 정상 SKIP 과 실패의 구분

- 유지됨: 게이트·설정·캘린더·손상 state·보류 표식·승인 이상·정산 실패는 실패이며 정산 검증 대상입니다.
- 빈틈 1: 봇을 실행하지 않는 SKIP 에서는 **state 파일이 없거나(캐시 복원 실패) 설정 종목 기록이 없어도**
  SKIP(성공)입니다. 다음 거래일 실행에서 드러납니다.
- 빈틈 2: 같은 경로에서는 자격증명·`{SYMBOL}_SEED` 같은 봇 설정 오류도 그날은 드러나지 않습니다.

## 4. 남은 한계·후속 과제

1. 조기폐장일에도 애프터아워 종료를 ET 20:00 으로 보므로, 그 전에 실행하면 정산도 다음 실행으로 미룹니다.
2. DRY 의 마감 후(애프터아워 중) 실행은 기존 레거시 동작 그대로입니다.
3. 정기 슬롯이 마감 후 시각이 되면 매일 SKIP(성공)이며 요약·텔레그램의 사유로만 드러납니다 (연속 SKIP 감시).
4. 주문 창이 닫힌 날의 LIFECYCLE 은 PREVIEW 를 생략하므로 PREVIEW 에서만 판정되는 보류는 다음 거래일에 드러납니다.
5. hosted 러너에서 프리장 대기가 상한을 넘으면 기존대로 실패합니다.

- 정상 SKIP(`skip`)·DRY 휴장(`dry-holiday`): 새 state 캐시 없음, 정산 검증 job `skipped`.
- 근거 누락(`evidence-missing` 등): 거래 job 이 성공해도 정산 검증 실패("정산 근거 파일이 없습니다").
- 강제 종료(exit 137)·1분 step timeout·run 취소: step output(`PARTIAL_FAILURE`/`ATTEMPTED`)이 **보존**됐고,
  state 캐시 저장과 정산 검증이 실행됐습니다.

- 덮지 않은 것: 유효한 근거의 정산 검증 **성공** 경로, self-hosted·단독 EXECUTE, 실제 봇·브로커·텔레그램.
- 관측: 사용 중인 `actions/*@v4` 등에 Node.js 20 지원 중단 경고가 있습니다 (이 PR 이전부터의 버전).
