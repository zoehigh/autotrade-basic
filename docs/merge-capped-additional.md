# 보정된 정상매수 + 추가매수 수량 합산 (`MERGE_CAPPED_ADDITIONAL`)

기본 **OFF**. 켜지 않으면 기존 동작과 완전히 같습니다 (`.env`: `MERGE_CAPPED_ADDITIONAL=true`).

## 문제
정상매수가 현재가 ×1.19 상한으로 낮춰지면(예: $118.10 → $111.51), 원래 주문표의 추가매수 단계 중
보정가 이상이던 것(예: $115.84)은 별도 주문으로 낼 수 없습니다(브로커 +20% 제한).
현재 코드는 이 단계를 **버리고 더 깊은 단계를 새로 만들어** 개수를 채웁니다.

## 동작 (ON)
1. 원래(보정 전) 정상매수가를 천장으로 한 추가매수 계단(`levels` 단계)을 원래 주문표로 봅니다.
2. 보정가 **이상**인 단계의 수량을 보정된 정상매수 주문(가장 낮은 정상매수)에 더합니다.
   LOC 는 종가가 보정가 이하이면 같이 체결되므로 원래 주문표와 같은 결과입니다.
3. 보정가 미만 단계만 추가매수로 남기고 깊은 단계는 더 만들지 않습니다.
   → 총 수량 = 정상 + `levels` (원래 주문표와 같음), 가격 중복 없음.

예 (SOXL 후반전): 정상 4주 @111.51(원래 118.10) + 추가 [115.84, 96.53, 82.74] →
**5주 @111.51** + 추가 [96.53, 82.74]. (OFF: 4주 + [96.53, 82.74, 72.40])

## 정산
합산 주문은 `total_qty = 정상 + 합산분`, `t_target = 정상 값`, `is_additional = False` 로 등록합니다
(`merged_additional_qty`, `normal_qty` 도 기록). 기존 비례 정산 `ΔT = (체결/total_qty) × t_target` 그대로:
- 완전체결: ΔT = t_target — 합산분은 T 를 올리지 않음 (분리 주문 기준선과 동일)
- 부분체결: 비례. 어느 단위가 체결됐는지는 알 수 없으므로 정상/추가 구분 없이 **비례 가정**
  (분리 주문에서 정상분이 먼저 체결되는 경우와 다를 수 있음)
- 순투입: 체결금액 기준이라 분리 주문과 동일, 지연 체결·재실행에도 이중 가산 없음

추가매수 표식(`[추가매수]`)을 주문 설명에 넣지 않습니다 — 넣으면 T 가 0 으로 처리됩니다.

## 가격 정정 도구와의 관계
합산 주문의 한도를 원래 매수가까지 올리면 합산된 추가 수량이 원래 주문표보다 높은 종가에서도 체결됩니다.
그래서 `ops/meritz_buy_loc_reprice.py` 는 합산 주문을 **SKIP** 합니다.

## 켜기 전 확인

`orders_meta` 의 `processed_filled_*`·T·`net_invested` 가 한 번만 반영됐는지 `verify_run` 으로 확인합니다.
