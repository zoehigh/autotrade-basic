# 보정된 정상매수 + 추가매수 수량 합산 (`MERGE_CAPPED_ADDITIONAL`)

기본 **OFF**. 켜지 않으면 기존 동작과 완전히 같습니다 (`.env`: `MERGE_CAPPED_ADDITIONAL=true`).

## 문제
정상매수가 현재가 ×1.19 상한으로 낮춰지면(예: $118.10 → $111.51), 원래 주문표의 추가매수 단계 중
보정가 이상이던 것(예: $115.84)은 별도 주문으로 낼 수 없습니다(브로커 +20% 제한).
현재 코드는 이 단계를 **버리고 더 깊은 단계를 새로 만들어** 개수를 채웁니다.

## 동작 (ON)
1. 원래(보정 전) 정상매수가를 천장으로 한 추가매수 계단(`levels` 단계)을 원래 주문표로 봅니다.
2. 보정가 **이상**인 단계의 수량을 보정된 정상매수 주문(가장 낮은 정상매수)에 더합니다.
   LOC 는 종가가 보정가 이하이면 같이 체결되므로 원래 주문표와 같은 결과입니다.
3. 보정가 미만 단계만 추가매수로 남기고 깊은 단계는 더 만들지 않습니다.
   → 총 수량 = 정상 + `levels` (원래 주문표와 같음), 가격 중복 없음.

예 (SOXL 후반전): 정상 4주 @111.51(원래 118.10) + 추가 [115.84, 96.53, 82.74] →
**5주 @111.51** + 추가 [96.53, 82.74]. (OFF: 4주 + [96.53, 82.74, 72.40])

## 정산
합산 주문은 `total_qty = 정상 + 합산분`, `t_target = 정상 값`, `is_additional = False` 로 등록합니다
(`merged_additional_qty`, `normal_qty` 도 기록). 기존 비례 정산 `ΔT = (체결/total_qty) × t_target` 그대로:
- 완전체결: ΔT = t_target — 합산분은 T 를 올리지 않음 (분리 주문 기준선과 동일)
- 부분체결: 비례. 어느 단위가 체결됐는지는 알 수 없으므로 정상/추가 구분 없이 **비례 가정**.
  **완전체결은 분리 주문과 동등하지만, 부분체결은 동등하지 않습니다 (전략 선택).**
  예: 정상 4주 + 합산 1주에서 2주만 체결되면 합산 주문은 ΔT = 2/5 = 0.4,
  분리 주문에서 정상 2주만 체결됐다면 ΔT = 2/4 = 0.5 입니다. (분리 주문에서 추가 1주가 먼저 체결되면
  ΔT = 0 이므로 분리 쪽도 어느 주문이 체결되는지에 따라 달라집니다.) 합산은 그 불확실성을 비례로 평균냅니다.
- 순투입: 체결금액 기준이라 분리 주문과 동일, 지연 체결·재실행에도 이중 가산 없음

추가매수 표식(`[추가매수]`)을 주문 설명에 넣지 않습니다 — 넣으면 T 가 0 으로 처리됩니다.

## 가격 정정 도구와의 관계
합산 주문의 한도를 원래 매수가까지 올리면 합산된 추가 수량이 원래 주문표보다 높은 종가에서도 체결됩니다.
그래서 `ops/meritz_buy_loc_reprice.py` 는 합산 주문을 **SKIP** 합니다.

## 켜기 전 확인
DRY 로 주문표(수량·가격)를 확인하고 텔레그램 주문 알림의 수량 표기를 확인하세요. 첫 체결 후
`orders_meta` 의 `processed_filled_*`·T·`net_invested` 가 한 번만 반영됐는지 `verify_run` 으로 확인합니다.

## 숫자 예시 (SOXL 후반전, 현재가 $93.71 → 상한 보정가 $111.51, 원래 정상매수가 $118.10, 추가 1주 단위)

**주문표**
| 방식 | 정상매수 | 추가매수 (1주씩) |
|---|---|---|
| 원래 주문표(보정 전, 이론) | 4주 @118.10 | 115.84, 96.53, 82.74 |
| 기존(OFF) | 4주 @111.51 | 96.53, 82.74, **72.40** (버려진 115.84 대신 깊은 단계를 새로 추가) |
| 합산(ON) | **5주** @111.51 (정상 4 + 합산 1) | 96.53, 82.74 |

**종가별 총 체결 수량** (LOC: 종가 ≤ 한도가면 체결, 체결가 = 종가)
| 종가 | 원래표 | OFF | ON |
|---|---|---|---|
| $118.0 / $115.0 | 4 / 5 | 0 / 0 | 0 / 0 (보정가 $111.51 초과 한도는 브로커 +20% 제한 때문에 낼 수 없음) |
| $111.0, $100.0 | 5 | 4 | **5** |
| $95.0 | 6 | 5 | **6** |
| $80.0 | 7 | 6 | **7** |
| $70.0 | 7 | 7 | 7 |

→ 종가가 보정가 이하이면 ON 이 원래 주문표와 같은 수량이고 OFF 는 1주 모자랍니다. 종가가 보정가를 넘는 구간은 어느 방식도 재현할 수 없습니다.

**부분체결 — 수량·T·순투입** (종가 $100, 기준 T = 5.0, 순투입 $1,000, 정상 주문 t_target = 1.0)
| 체결 | 합산 주문(5주) ΔT / T / 순투입 Δ | 기존 분리(정상 4주+추가 1주), 정상 먼저 체결 ΔT | 기존 분리, 추가 먼저 체결 ΔT |
|---|---|---|---|
| 1주 | +0.20 / 5.20 / +$100 | +0.25 | +0.00 |
| 2주 | +0.40 / 5.40 / +$200 | +0.50 | +0.25 |
| 3주 | +0.60 / 5.60 / +$300 | +0.75 | +0.50 |
| 4주 | +0.80 / 5.80 / +$400 | +1.00 | +0.75 |
| 5주(완전) | **+1.00 / 6.00 / +$500** | **+1.00** | **+1.00** |

- **순투입은 모든 경우에 같습니다**(체결금액 기준). **완전체결 T 도 같습니다.**
- **부분체결 T 는 합산이 비례(f/5)** 라 분리 주문의 두 경우(정상 먼저: f/4, 추가 먼저: (f−1)/4) 사이에 놓입니다 — 어느 단위가 먼저 체결됐는지 알 수 없어서 비례로 평균냅니다. 마지막 체결까지 가면 모두 +1.00 으로 수렴하고 재실행·지연 체결에서 이중 가산은 없습니다.

## "큰수 이상"의 해석과 같은 가격
"큰수"를 **상한 보정으로 낮춰진 정상매수가(보정가)보다 높은(이상인) 원래 주문표의 가격대**로 해석했습니다.
- 보정가와 **같은 가격**의 추가매수 단계는 **합산합니다** (`price >= 보정가`). 예: 보정가 $110.00, 단계 $110.00(=550/5) → 정상 4 → 5주로 합산, 별도 추가매수로 남지 않음.
- 보정가 **바로 아래**(예: $109.00)는 합산하지 않고 추가매수로 유지합니다.
- 호가 단위는 내림(floor)이라 $111.51 같은 값은 부동소수 때문에 $111.50 으로 내려갈 수 있습니다 (경계 테스트는 정확히 표현되는 값 사용).
